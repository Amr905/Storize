### 2. Field mapping to the domain entities (for T-006)
Column set, nullability and type line up one to one with `Target`, `Content`, `MediaFile`, `LoginAccount`, `CheckRun`, `ActivityEvent`, `GovernorLease`/`GovernorBucket`. Mapping notes:
- `Content.extras` and `ActivityEvent.payload` are `Map` in the domain and `TEXT` JSON (`extras_json`, `payload_json`, nullable) in SQL. T-006 must encode and decode, and map NULL to `{}`.
- Timestamps are epoch ms and come back as **UTC** `DateTime`s with millisecond precision. A domain `DateTime` with microseconds, or a local one, will not `==` its stored round trip (`DateTime ==` compares `isUtc`). A local-zone input is stored as the same instant (tested).
- The domain `unsavedId` is 0. A companion built from an entity with `id: Value(0)` stores a row with id **0** (QA test `an explicit id of 0 is stored as id 0`). T-006 must leave `id` absent.
- `check_run.scope` is only `STORIES` or `POSTS`; `CheckScope.all` throws `ArgumentError` from the converter before SQL.

### 7. Isolate sharing (code review, not runnable here)
Source: `~/.pub-cache/hosted/pub.dev/drift_flutter-0.3.1/lib/src/native.dart` and its README.
- With `shareAcrossIsolates: true`, `driftDatabase()` looks up a port named after the database in `IsolateNameServer`. If one exists, it connects to that `DriftIsolate`; otherwise it spawns a dedicated isolate that opens the one real `NativeDatabase` (running the `setup` callback), registers itself under that name, and serves all clients. A race between two spawners is handled (the loser exits and retries). The server stops after the last client disconnects.
- `IsolateNameServer` is process wide (it lives in the Dart VM / engine, not per engine). The workmanager background isolate runs in the same app process, in its own FlutterEngine, so both isolates find the same server and share **one** SQLite connection. Statements and transactions from both are serialised by the server, and drift forwards table-update notifications to every client, so UI streams re-emit after background writes. If the process was killed, the background task is simply the first client and spawns the server. Since all access goes through one connection, `GovernorLeaseDao`'s read-modify-write transactions are atomic across isolates.
- The `setup` closure captures nothing (it only uses its `db` argument) and `getApplicationSupportDirectory` is a top-level tear-off, so the options are sendable to the spawned isolate. The PRAGMAs (WAL, `busy_timeout`, `synchronous = NORMAL`) run on the server connection once. WAL/`busy_timeout` only matter if a second process ever opens the file, which workmanager does not do, so they are harmless insurance.
- `PRAGMA foreign_keys = ON` is in `beforeOpen` and runs on the shared connection each time a client opens. The test confirms `PRAGMA foreign_keys` = 1.
- Verdict: the design is correct. **Caveats for T-021 (background dispatcher):** call `DartPluginRegistrant.ensureInitialized()` before `StorizeDatabase.open()` (path_provider needs it in the headless isolate); `close()` the database when the task ends (the README says the server only stops when all clients close; a leaked client keeps the isolate alive); and test on a device, because `open()` is not exercised by any automated test.

### Developer decisions
| Decision | Judgement | Reason |
|----------|-----------|--------|
| Extra NOT NULLs beyond §3 (platform, status, kind, posted_at, detected_at, flags, counts) | **OK** | Each one matches a required field of the domain entity; nullable columns match the nullable entity fields exactly (checked all 7 entities). Prevents NULL rows that the mappers could not read |
| `governor_lease` has no FK | **OK** | §3 declares none; the lease can be written before the account row and outlives account removal. Cost: an orphan row after an account is deleted, which is a few bytes and harmless |
| Row classes named `*Row` | **OK** | Avoids clashing with the domain entities and makes the mapping step in T-006 explicit |
| UTC `DateTime`s stored as epoch ms | **OK** | §3 says so. Caveat: millisecond precision and UTC-only (section 2) |
| `shareAcrossIsolates: true`, WAL, `busy_timeout` 5000 | **OK** | Section 7. Unverified on a device; caveats listed for T-021 |
| DB at `getApplicationSupportDirectory()/storize.sqlite` | **OK** | Matches §3 "App files (private): files/ ... storize.sqlite" (the drift_flutter default would be the documents directory) |
| Library query with no kind or target does a full scan, documented, no index | **OK** | Measured: walks `idx_content_kind_posted_at` plus a sort, 145 ms at 5,000 rows. The UI always sets a kind. An extra `posted_at` index is not worth the write cost |
| Generated code committed; package `analysis_options.yaml` excludes generated folders | **OK** | `melos run gen` gives no diff; analyzer clean. The exclude covers only `test/db/generated/**` and `lib/db/schema_versions.dart` (`*.g.dart` is excluded by the root config) |
| `insertIfNew` overwrites the `contentId` of the media companions | **OK** | Matches the `ContentRepo` contract ("IDs ignored and replaced", `MediaFile.unsavedContentId = 0`) and is documented. It is an unusual API shape but harmless |
