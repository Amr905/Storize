## Probe results

1. **Mirror drift.** Rules match line for line (limits 100/255/4, forbidden `:*?"<>|\`, `..`, leading `.`, trailing `.`/space, absolute/`~`/`X:`). One drift: the Cf list in `plugin_rules.dart` is incomplete, see F-1. Lone surrogates: both Kotlin (type SURROGATE) and the mirror accept them; the lib sanitiser replaces them, so no lone surrogate reaches the plugin.
2. **Names.** All hostile cases fine. Remaining gap: UTF-8 bytes, F-3.
3. **FileMediaCache.** Ids are `int`, so `../` cannot occur; extreme ids (+-2^62) stay inside `part/` and `thumbs/`, and a scan of the temp root shows nothing written elsewhere. Resume after a failed stream gives exactly the written prefix, a later append continues it byte for byte. Concurrent appends to one id lose data (F-2). Empty stream creates an empty part, length 0.
4. **Error mapping.** Every code maps as designed; messages and `toString` carry only the code (a probe with a path and `?sig=` in the native message never appears). `SOURCE_NOT_FOUND` on delete/exists/size is false/null. A foreign authority gives `GalleryWriteFailed(INVALID_ARGUMENT)` on delete; exists/size give false/null.
5. **Contract parity.** Differences found, see F-4.
6. **Guardrails.** Clean (table above).

## Findings

| # | Severity | Finding | Repro / evidence |
|---|----------|---------|------------------|
| F-1 | minor | `plugin_rules.dart` `_hidden` misses 46 Cf code points that `Character.getType` classifies as FORMAT, so the mirror would accept names a device rejects: U+0600-0605 (Arabic number signs, relevant for Arabic users), 06DD, 070F, 0890-0891, 08E2, 180E, FFF9-FFFB, 110BD, 110CD, 13430-1343F, 1BCA0-1BCA3, 1D173-1D17A, E0001. No product impact: the lib sanitiser (`display_names.dart`) is a superset and strips all of them (QA test passes). Fix: copy those ranges into the mirror. Android ICU may carry newer Cf characters than JDK 21; P-4 on a device cannot hurt. | `qa_t010_test.dart`, skipped test "plugin_rules.dart rejects every code point the JDK hides". Remove the `skip:` after fixing the mirror. |
| F-2 | minor | Two concurrent `append`s on one id lose bytes: 2 x 5000 bytes gave a 5000-byte part. Documented as unsupported in the class doc, and the governor allows one in-flight call, so the risk is low. A second isolate resuming the same id could still corrupt a download; consider a per-id lock or a lock file. | QA test "concurrent appends ... lose data (unsupported)" asserts the observed 5000..10000 range. |
| F-3 | minor | Length limits count UTF-16 units (matches `InputValidation.kt`), not UTF-8 bytes. ext4/f2fs limit names to 255 bytes. A 64+64 CJK name is about 400 bytes and a 100-CJK folder 300 bytes. Instagram usernames and IDs are ASCII, so only a non-ASCII remote ID triggers it. The plugin has the same gap (see T-009 F5). | QA test "KNOWN GAP"; the desired assertion is a skipped test. |
| F-4 | minor | Fake and real stores differ: (a) the fake returns `relativePath = relativeDir` (`nour_k`), the real one `Pictures/Storize/nour_k/`; (b) the fake `save` succeeds for a missing source, the real one throws `GalleryWriteFailed(SOURCE_NOT_FOUND)`; (c) the fake does not validate names, rename duplicates, or model the Movies fallback. Also: `exists`/`size` can throw `GalleryPermissionDenied`/`GalleryStorageFull` (real), while the port doc promises only `GalleryWriteFailed`; and a wrong-typed native answer escapes `PluginGalleryStore.save` as a raw `TypeError` (T-009 wrapper's generic cast), not a `GalleryStoreException`. All are low risk (native never answers a wrong type). Suggested: make the fake return `Pictures/Storize/<dir>/` and fail on a missing source when the path is not a fake-cache path, and align the port doc. | QA tests in "QA contract parity" and "QA PluginGalleryStore error mapping" pin current behaviour. |

Other notes (no action): `.tmp` thumbnail leftovers after a process kill are not cleaned (`cleanupOrphans` only scans `part/`); two concurrent thumbnail writes for one id share a temp name. Both harmless.
