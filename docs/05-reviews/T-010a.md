## Review by reading

1. **Kotlin.** `StatFs.availableBytes/totalBytes` exist since API 18, fine for minSdk 26 / compileSdk 36 (CI compiled). It uses `availableBytes`, not `freeBytes`: correct. `@Suppress("DEPRECATION")` on the local `val path` is valid and applies to the deprecated `getExternalStorageDirectory` call (API 29+). The constructor parameter named `open` is a soft keyword and compiled. Threading: off the main thread. Exits: `background` always sends exactly one reply (success, error through `deliver`, or UNAVAILABLE when detached/rejected); `StorageStatsOps` itself only returns or throws `PluginException(IO_ERROR)`, matching `MediaStoreOps` for I/O failures (`IO_ERROR`). Messages are constant and contain no path. Only `RuntimeException` is caught; an `Error` falls to `runCatching` and is mapped to UNKNOWN with `Class: message` (see N-2).
2. **Volume.** `MediaStoreOps` writes to `VOLUME_EXTERNAL_PRIMARY`, and `getExternalStorageDirectory()` is the primary shared storage, so both refer to the same volume. On API 29+ `/storage/emulated/0` is a FUSE view over the data partition (or the adopted volume when adoptable storage is used as internal), and `StatFs` on it needs no permission. Recommendation: keep it. A move to `StorageStatsManager.getFreeBytes(UUID)` is not needed; it would also count cache that the OS can clear, which is optimistic for a guard. `getExternalStorageDirectory` is deprecated but the mount-point value is still correct; a later cleanup could use `StorageManager.primaryStorageVolume.directory` (API 30+) with a fallback.
3. **Dart.** 64-bit values, doubles, negative/zero/null/missing keys, and non-map answers are checked (QA tests). A missing plugin gives UNAVAILABLE. No error carries a path.
4. **`catch TypeError`.** Low masking risk. Each `try` wraps only the single `_plugin.*` call; the `GalleryFile` construction and `_map` sit outside the try, so a bug in the store's own code is not converted. What it can hide is a cast bug inside the plugin wrapper, which is reported as BAD_RESPONSE; that is the intent. The `ignore_for_file` covers the whole file for the `avoid_catching_errors` lint (N-1).
5. **F-1.** Exact match both ways (see AC). Android ICU may include Cf characters newer than JDK 21; P-4 on a device covers it.
6. **Guardrails.** No pubspec or gradle changes; `storize_domain` imports only model/meta/Dart (only an enum name mentions Instagram); governor untouched.

## Findings

| # | Severity | Finding |
|---|----------|---------|
| F-1 | minor | The Dart side does not re-check `free <= total` (Kotlin clamps). `StorageStats(20, 10)` passes through. Harmless for the threshold checks, but `ComputeStorage` (T-021/T-0xx) must not compute `total - free` or a percentage without clamping. Pinned by a QA test; if the Lead wants defence in depth, clamp in `storageStats()`. |
| F-2 | minor | `PluginStorageInfo.freeBytes()` and `totalBytes()` each make a native call, so the pair is not a single snapshot (two reads, QA test). Fine for a guard; a use case that shows "used" space should read both close together or the port should gain a combined method. |
| F-3 | minor | A StatFs failure on an unmounted volume gives IO_ERROR (good), but callers see `StorizePlatformException`; the port doc says "unknown, do not stop downloads". T-018/T-021 must catch it. Not a bug here. |
| N-1 | note | `// ignore_for_file: avoid_catching_errors` is file-wide; prefer `// ignore:` on the four catches. |
| N-2 | note | `UNKNOWN` messages from `mapThrowable` include `t.message`, which for an unexpected `Error` could carry a path. Existing T-009 behaviour, not new here. |
