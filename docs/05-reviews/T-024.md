## Findings

- **F1 (Medium, token, spec-owned)**: light `onPrimary` on `primary` is 4.29:1; it applies to filled buttons, the FAB and the Switch thumb on its track (`storize_theme.dart:11-12`, `filledButtonTheme`). The §5.2 values give this ratio, so it needs a UX decision: darken primary to about #C93F17 or treat button labels as large/bold text (13 sp Medium is not "large"). Tokens not changed.
- **F2 (Medium)**: light `primary` as text/icon on `surface` is 4.05:1. TextButton labels (`StorizeTextButton`, default foreground = primary) and active-tab colour use it. Same fix as F1.
- **F3 (Low)**: light `warning.color` #B26A00 is 4.01:1 on surface; badges use `onContainer` (fine), but do not use `warning.color` for text. Add a doc comment or a lint-style test.
- **F4 (Low)**: no automated contrast test exists. Suggest a test asserting the ratio of every onContainer/container pair and onPrimary/primary against 4.5 so F1-F3 are tracked.
- **F5 (Low)**: category tag colours differ from the mockup S-07 (mockup: Person who agreed purple, Public creator green, Own/Client blue; code: own ember, consented blue, public purple, `storize_colors.dart` tag tones). UX §5.2 does not specify them; Lead/UX to decide. Also the mockup avatars are gradients and the status badge sits at the row's top end; the golden TargetRow puts the badge on the second line with an icon (acceptable: §6 requires text+icon).
- **F6 (Info)**: goldens depend on Roboto/MaterialIcons from the pinned Flutter SDK (`golden_helpers.dart`); if the font directory is not found, tests silently fall back to Ahem and goldens fail. Linux-only, as documented.
- **F7 (Info, fixed by QA)**: original RTL tests did not guard against non-directional padding (mutation survived). Two tests added; see AC3.

## Verdict

**PASS** with findings. Implementation meets all four ACs; F1 and F2 are contrast shortfalls inherited from the UX token values and need a Lead/UX decision rather than a developer fix. No product code was changed by QA.
