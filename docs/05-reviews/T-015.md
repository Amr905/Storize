### Mode selection (task item 1)
Covered above. Not found: any path from a non-`SchemaChanged` failure to page mode. `_run` calls `page` only when
`first.failureOrNull is SchemaChanged` and the policy is not `directOnly`; a guardrail test (existing) pins that single call site.

### openMedia (item 2)
- **Resume:** 206 with a `Content-Range` that starts at `fromByte` is streamed; every other start (49, 51, 0), `bytes */200`, another unit, `bytes 50-/200`, an empty or truncated header, or no header is refused with no bytes emitted. A 200 (Range ignored) skips the prefix correctly at chunk boundaries 1, 10, 29, 30, 31, 59, 60 and 99; a 200 shorter than `fromByte` is `range_beyond_end`; a 200 of exactly `fromByte` bytes is an empty successful stream (the file was complete; fine). 416 is `MediaStreamFailure(statusCode: 416)`, not expiry, and the body is cancelled unread. 206 shorter than `Content-Length` is `truncated` after the valid bytes.
- **Redirects:** 301, 302, 303, 307, 308 are failures with the status; exactly one request, no body. `DartIoCdnHttp` against a real server: a 302 to another host is not followed (the second server saw 0 hits).
- **Cookies:** a real server saw only `range`, `host`, `accept-encoding`, `user-agent`; no `cookie`, `authorization` or `x-ig-*`.
- **Allowlist:** 3000 random URL mutations (schemes, userinfo, ports, look-alike and encoded hosts, backslash and query tricks): everything that reached the client was https, no userinfo, port none/443, host in the list. Eight handcrafted bypass attempts are refused without a request.
- **Backpressure:** 64 MB produced lazily, consumer yielding every 64 chunks: the producer never ran more than 4 chunks ahead. The idle timeout does not fire during a 300 ms pause with an 80 ms timeout. Cancel in the skip phase closes the body.
- **No URL in logs or errors:** client and body errors of 6 kinds (SocketException with the URL as text, HandshakeException, FormatException, StateError, TransportException, a bare String) and 12 HTTP statuses: no `ZZFAKE`, host, path or `sig=` in any error text or log line.

### WebView lease (item 3)
- Property test (20 seeds x 100 random steps of acquire/release/advance/tick on two instances, one repo): never both held while renewals run. Same owner name in two isolates still excludes (holder is the instance id). A wrong-instance release does not free the row.
- Crash: blocked until exactly TTL (`ttl - 1 ms` false, `ttl` true). A healthy holder renewing at ttl/3 for 30 simulated minutes is never taken over. A lapsed hold (`maxHold`) frees the row at the next tick.
- Skew: a clock jump of -1 h with a crashed holder: a new instance takes the row at once (T-012a rule works on key -1). A release writes the epoch and is never blocked by skew.
- Key -1 vs governor: both rows coexist, never block each other, the lease never writes a real account row and its own bucket stays 0. The table has no FK and `loginAccountId` is a plain integer primary key, so -1 is valid.
- Findings F2 and F5 below (lease loss undetected; late-answer race).

### Seen breaker (item 4)
Fail-closed on async and synchronous store errors; a trip is visible in memory at once and the store changes only when the write completes (`flush` waits); a stale "not tripped" read that completes after a trip does not clear it; a failing `clear` leaves memory tripped; `reset()` waits for a pending trip write and ends clean; the only `clear()` on a store in `lib/` is in `SeenGuard.reset()` (grep). Finding F6 (no timeout on a hanging read).

### UsernameCache (item 5)
EC-5 works: `remember('u1','new')` leaves the row at the old name, so RunCheck still sees old != new. F7: the overlay is never invalidated and wins over a newer row.

### Findings
| ID | Severity | Finding | Reproduce / proof |
|---|---|---|---|
| F1 | Low-Medium | `_pageStories` loads one user per call and lost the all-names-first check of `PageExtractor.fetchStories`. If user 2 is `username_unknown` (or the breaker trips, or the gate flips) after user 1 was loaded, the failure is treated as "page mode did not run": the direct `SchemaChanged` is returned and `PAGE_MODE_USED` is **not** counted although one WebView page was loaded (3 tokens). Loaded data is discarded. With N users the waste is up to N-1 loads. Fix: check every username before the first load (or count a use once any page was loaded). | `qa_t015_modes_test.dart`, two `PIN (QA-T015-F1)` tests (`pageModeUses == 0`, WANTED 1). |
| F2 | Low | If the lease is lost (frozen process past TTL, or renewals failing for more than the TTL), the old holder still reports `isHeld` until its next tick, then only logs `lease_lost`. Afterwards `tryAcquire` of the same owner still returns true and the stale owner blocks every other owner in that isolate. S-02 and a page load can overlap on the app-wide cookie jar. Needs a loss signal for T-026, or a `tryAcquire` that checks `_held`. | `qa_t015_lease_test.dart` `PIN (QA-T015-F2)`; renewal-failure test. |
| F3 | Low | A 206 reply to a request without Range (`fromByte` 0) is accepted whatever its `Content-Range` start is (a 206 starting at byte 500 yields wrong bytes). Realistic only for a broken CDN. Fix: require start 0 when `fromByte` is 0. | `qa_t015_media_test.dart` `PIN (QA-T015-F3)`. |
| F4 | Low | A 206 without `Content-Length` that ends early is a success: the `Content-Range` total is not used to detect truncation. `dart:io` reports `Content-Length` for CDN replies, so this needs chunked encoding. | `PIN (QA-T015-F4)`. |
| F5 | Low | Race in `tryAcquire` in one isolate: attempt 1 times out (3 s), attempt 2 starts, then attempt 1's late answer releases the row while attempt 2 is still in flight. Attempt 2 then returns true on an already released row, and another isolate can take it until the next renewal tick (up to ttl/3 = 40 s). Needs a slow repo plus two acquires in the window. Fix: keep a generation counter and release only when no later attempt exists. | `PIN (QA-T015-F5)`. |
| F6 | Low | `SeenGuard.refresh()` has no timeout: a store read that never completes hangs the stories fallback (it runs before the governor, so nothing else bounds it). Fail-closed covers errors, not hangs. | `PIN (QA-T015-F6)`. |
