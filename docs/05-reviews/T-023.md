### Never throws
`checkForUpdate` wraps everything in `try ... on Object`, so it cannot throw (this also covers json cast TypeErrors; there are no unchecked casts anyway: all fields use `is` checks). Verified with: empty, `null`, array, number, truncated JSON, tag as number/null/list, `html_url` as number/map, body as number/list/map/null, invalid URIs, 5 MB body (under 5 s), 1 MB single line, sha at the end of a huge body, tags `v999999999999999999999.0.0`, `vv1.2.3`, Arabic-Indic and fullwidth digits (`\d` is ASCII-only in Dart, so rejected), `v-1.2.3`, `v1..3`, `v1.2.3-`, NUL. Huge numbers: `int.tryParse` returns null on the VM so they are rejected (on web it would be lossy, irrelevant for Android).

### Timeouts and timers
- `Future.timeout(timeout)` bounds the whole call even if the adapter never completes: real-clock test (200 ms) returns `none` well under 2 s; `testWidgets` fake-clock test shows the result is still pending at 2 s and `none` at 4 s with a 3 s timeout.
- `testWidgets` fails on pending timers; neither the timeout path nor the fast-success path leaves one.
- Caveat (Low): the dio request is not cancelled on timeout (no `CancelToken`); with the real adapter dio's own connect/send/receive timeouts (same value) stop it.

### Security: `html_url`
Rejected: http, javascript:, intent:, file:, market:, relative, scheme-relative, empty. **Accepted: any https host** (e.g. `https://evil.example/x`, and `https://github.com@evil.example/x` which parses to host `evil.example`). Tests document this.

### Spec fit
- `required` only when current < min-supported AND remote newer: sensible. If the remote is not newer then no newer build exists, so forcing "update" would trap the user with nothing to install. The case is only reachable through a release-notes typo (min-supported greater than the latest tag) or a downgraded latest release. Showing `none` there is the safe choice. The opposite typo (min > tag, remote newer) yields `required`, which is also tested. I agree with the decision.
- Malformed min-supported ignored (available), malformed sha null: fail-open for the optional hint, consistent with "silent on errors" (NFR-9). Note a malformed min-supported can therefore never force an update; acceptable.
- Pre-release follows SemVer, `+build` ignored, exactly three numeric parts, lowercase sha: sensible.
- sha with trailing file name (`sha256: <hex> app-prod.apk`) parses; `sha256: app-prod.apk <hex>` gives null.
