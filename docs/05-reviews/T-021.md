## Findings

- **F1 (Low): `PluginGalleryStore.findExisting` is not "any failure to null".** It catches only `StorizePlatformException` and `TypeError`.
  Any other error from the plugin (a StateError, FormatException or other Exception) propagates to `DownloadPending`.
  The current `_call` only produces those two types, so this is unlikely in practice. Fix: `on Object` (or `catch (_)`).
  Reproduce: un-skip the 3 tests in `packages/storize_data/test/qa/t021_scheduler_qa_test.dart` (group `findExisting`).
- **F2 (Info): unexpected errors return `false` (retry with back-off)**, including in the one-off `download` task, and WorkManager has
  no retry cap. Each retry is rate-limited by the exponential back-off (5 min start), and a persistent error is logged. Acceptable for
  MVP; consider a run-attempt cap if the device test shows churn.
