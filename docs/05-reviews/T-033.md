### Findings
1. **Medium: `logOut` step order.** `account_providers.dart` clears the vault session, then `setStatus(loggedOut)`, then `cancelAll()`. If `setStatus` throws, the session is gone but the status is still `active` and the schedules still run: the UI looks logged in with no session. Repro: `test/qa/t033_settings_qa_test.dart` "setStatus failure leaves no active-without-session" (`status=active sessionPresent=false`). Suggested order: `cancelAll`, then `setStatus(loggedOut)`, then `sessionStore.clear`. Then any partial failure leaves "loggedOut with a stale session" (safe) rather than the reverse.
   A `cancelAll` failure leaves loggedOut + cleared session (consistent, schedules linger; Low).
