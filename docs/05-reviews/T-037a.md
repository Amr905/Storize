# T-037a: dev-only debug tools

## How to open the dev tools

Separate entry point (chosen over a `kDebugMode` route, so a release build, which uses `lib/main.dart`, has no path to it):

```
cd app && flutter run --flavor dev -t lib/main_dev_tools.dart
```

It builds the normal production composition (`composeProduction`, foreground), initializes WorkManager, and shows `DevToolsScreen` in place of the app. Pick a target in the dropdown (the synthetic seed target is hidden). `lib/main.dart` never imports `lib/debug/tools/` (enforced by `app/test/debug/tools/dev_tools_test.dart`). Strings are plain English; `lib/debug/` is already outside the string audit.

## Actions

| Button | What it does |
|---|---|
| Run check now (background) | `Scheduler.checkNow()` (scope all): the expedited one-off WorkManager task, which runs in the background isolate even after the app closes. |
| Page-mode story load | One `fetchStories` for the chosen target through a real `InstagramPlatform` whose direct mode is a stub that answers "schema changed" without any request. The platform's own fallback then runs the real `PageExtractor`: `RequestGovernor`, a `GovernorWebViewLease` on the shared lease table, the seen-mutation block hook and the persisted seen breaker. Busy or rate limited is shown as such and not retried. |
| Cookie count | `COUNT` of `instagram.com` cookies in the WebView cookie store (`CookieManager.getCookies(...).length`). Names and values are never read. After a page-mode run it should be 0 (page data is cleared). |
| Probe + CDN check | `IgProbe.run` (IG-1..IG-5, governed) for the chosen target, then one governed direct `fetchStories` to get up to 2 media, then `IgProbe.checkCdn`. Shows `ProbeReport.render()` unchanged. If there are no stories the CDN part is skipped. |
| Seed library | Inserts N (default 2000) rows, remote id `seed_<i>`, status done, placeholder media (`placeholder://seed/<i>`), under a paused synthetic target `seed_user` (remote id `seed_target`). No network. Running it again adds nothing. |
| Clear seed | Deletes only rows of the synthetic target whose remote id starts with `seed_`, then the synthetic target if nothing else is under it. Real targets and content are untouched. |
| Recent log (50) | Last 50 lines of the rotating diagnostic log files (already sanitized by the logger), e.g. `accepted=... blocked=...`. |

## Notes

- Page mode builds its own `GovernorWebViewLease` (instance id `<holder>-devtools`) because the composition keeps its lease private; the lease table is shared, so mutual exclusion with the app and background isolate holds.
- The platform-level `ExtractionPolicy` has no "page only" option, hence the stub direct mode. No change to `storize_instagram` was needed.
