## Findings
1. **Medium: setup can be skipped for good.** `onboardingDone` is set in `LoginController._finishStaged` right after login, before S-03. Killing the app at S-03 means the next launch goes to the Library, and notification permission (Android 13+), battery exemption and the Android 8-9 storage prompt are never asked. S-03 stays reachable from the Activity gap action and Settings, so it is recoverable, but a fresh user gets no prompt. Suggest setting the flag at S-03 Done/Skip, or keeping a separate `setupSeen` flag.
2. **Low: gate defaults to `true` while loading** (`composition_production.dart:178`). `gate_qa` shows the gate reads true first and then false on a fresh install. The router refresh then redirects to S-01 (existing router tests), so no persistent bypass. A deep link on cold start can briefly build its target page. Safer: hold the redirect while loading.
3. **Low: no startup sweep of staging id 0.** A crash between `save(0)` and `clear(0)` leaves a valid session in the vault. Nothing in the app reads id 0 except the login platform, and the next login overwrites it, so it is never used. It is still a second valid cookie set at rest. Suggest `sessions.clear(0)` at startup.
4. **Low: rotation during a permission prompt.** `PermissionOps.detach()` answers `denied` while the system dialog is still up. This is not permanent, so the user can retry. S-03 re-checks on resume.
5. **Info:** the Kotlin side has only `PermissionPolicy` unit tests (4). `PermissionOps` was not run on a device or emulator.

No cookie, token or query-string leak found in logs, state or error text.
