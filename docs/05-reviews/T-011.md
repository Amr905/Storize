### Redaction bypass hunt: results
Held (no leak): URL-encoded single-level `%3D`, `;`-joined without spaces, tabs/spaces around `=` and `:`, uppercase header and cookie names, HTTP/2 `cookie:` lines and `:authority:` neighbours, CRLF header lines, JSON with escaped quotes, JSON with `\u`-escaped VALUE, curl commands, quoted values with spaces, uppercase hosts, ports, userinfo, `scontent-*.cdninstagram.com`, `instagram.f*.fbcdn.net`, `video.*`, HTTP and HTTPS, query after/before fragment, multi-URL `srcset`, look-alike hosts (`cdninstagram.com.evil.io`), URLs in stack traces and Dio-style errors, `Error.toString` with cookie, JSON-escaped URLs (`https:\/\/`), idempotence.

Truncation: redaction runs first and the cut second, so a secret straddling the 4000 boundary cannot leave a prefix. Tested for pad 3970..4001 (keys) and 3950..4001 (URLs): no fragment survives. The crash marker (first line, 200 chars) was tested for pad 180..205: no fragment survives.

ReDoS: 16 adversarial 100 KB inputs (unterminated quotes, repeated keys, long whitespace, repeated `Bearer`, `v1:`, `cookie:`, escaped quotes). Worst case about 150 ms, all linear-looking. A 2 s ceiling test is included.

Cannot handle (documented, not fixable by pattern): base64 of a cookie; bare token with no key (developer note); raw PIN with no key.

### Crash hooks
- Chaining: not chained (F3). `uninstall` restores previous handlers exactly and does not clobber a handler installed later.
- `PlatformDispatcher.onError` returns `true` (handled). Reasonable: no remote reporting (NFR-6); the app keeps running. Side effect: genuinely fatal async errors do not kill the process, but they are logged and marked.
- Install idempotence: a second `install` replaces the first; one error gives one log entry. Not chained, so no duplicates.
- `runGuarded` captures sync and async errors (see AC 3). Returns `null` on sync throw.
- Hooks never throw, even with log and marker both failing.

### APP_CRASH assessment
- Exactly once: `clear()` returns true only for the caller that deleted the file, so concurrent callers and isolates cannot double-report.
- No secrets: marker holds type (sanitised), first line redacted and cut to 200 chars, and a timestamp; no stack. Re-redacted on read, so a tampered marker is also cleaned. Bare tokens with no key are the documented limit.
- "First marker wins": agree. The first error is the likeliest root cause and later errors are often follow-ons; the full set is in the log file anyway.
- "Non-fatal FlutterErrors count as crashes": **recommend changing to fatal-only (or a separate `APP_ERROR`-style event)**. A rendering overflow or a failed image decode calls `FlutterError.onError` while the app keeps running, so the user would see "app crashed" in S-11 after a layout glitch, and the marker would then also hide a later real crash (first wins). Suggested rule: write the marker only from `PlatformDispatcher.onError` and the zone (which are uncaught async/isolate errors), and for `FlutterErrorDetails` only when `details.silent == false` and the library is not `rendering`/`image resource`/`widgets library` build errors; or simply log non-fatal ones without a marker. Not a blocker: severity minor/major-product decision for the Lead. A true process death (native crash, OOM kill) leaves no marker at all with any of these hooks; that is outside this task.
- Debug console leak: `presentError` prints the unredacted exception in debug builds only (`kDebugMode`). Release builds never print it. Risk: a developer pasting debug console output into an issue on the public repo. Acceptable; suggest a note in CONTRIBUTING, not a code change.
