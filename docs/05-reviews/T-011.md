### Redaction bypass hunt: results
Held (no leak): URL-encoded single-level `%3D`, `;`-joined without spaces, tabs/spaces around `=` and `:`, uppercase header and cookie names, HTTP/2 `cookie:` lines and `:authority:` neighbours, CRLF header lines, JSON with escaped quotes, JSON with `\u`-escaped VALUE, curl commands, quoted values with spaces, uppercase hosts, ports, userinfo, `scontent-*.cdninstagram.com`, `instagram.f*.fbcdn.net`, `video.*`, HTTP and HTTPS, query after/before fragment, multi-URL `srcset`, look-alike hosts (`cdninstagram.com.evil.io`), URLs in stack traces and Dio-style errors, `Error.toString` with cookie, JSON-escaped URLs (`https:\/\/`), idempotence.

Truncation: redaction runs first and the cut second, so a secret straddling the 4000 boundary cannot leave a prefix. Tested for pad 3970..4001 (keys) and 3950..4001 (URLs): no fragment survives. The crash marker (first line, 200 chars) was tested for pad 180..205: no fragment survives.

ReDoS: 16 adversarial 100 KB inputs (unterminated quotes, repeated keys, long whitespace, repeated `Bearer`, `v1:`, `cookie:`, escaped quotes). Worst case about 150 ms, all linear-looking. A 2 s ceiling test is included.

Cannot handle (documented, not fixable by pattern): base64 of a cookie; bare token with no key (developer note); raw PIN with no key.

### Crash hooks
- Chaining: not chained (F3). `uninstall` restores previous handlers exactly and does not clobber a handler installed later.
- `PlatformDispatcher.onError` returns `true` (handled). Reasonable: no remote reporting (NFR-6); the app keeps running. Side effect: genuinely fatal async errors do not kill the process, but they are logged and marked.
- Install idempotence: a second `install` replaces the first; one error gives one log entry. Not chained, so no duplicates.
- `runGuarded` captures sync and async errors (see AC 3). Returns `null` on sync throw.
- Hooks never throw, even with log and marker both failing.

### APP_CRASH assessment
- Exactly once: `clear()` returns true only for the caller that deleted the file, so concurrent callers and isolates cannot double-report.
- No secrets: marker holds type (sanitised), first line redacted and cut to 200 chars, and a timestamp; no stack. Re-redacted on read, so a tampered marker is also cleaned. Bare tokens with no key are the documented limit.
- "First marker wins": agree. The first error is the likeliest root cause and later errors are often follow-ons; the full set is in the log file anyway.
- "Non-fatal FlutterErrors count as crashes": **recommend changing to fatal-only (or a separate `APP_ERROR`-style event)**. A rendering overflow or a failed image decode calls `FlutterError.onError` while the app keeps running, so the user would see "app crashed" in S-11 after a layout glitch, and the marker would then also hide a later real crash (first wins). Suggested rule: write the marker only from `PlatformDispatcher.onError` and the zone (which are uncaught async/isolate errors), and for `FlutterErrorDetails` only when `details.silent == false` and the library is not `rendering`/`image resource`/`widgets library` build errors; or simply log non-fatal ones without a marker. Not a blocker: severity minor/major-product decision for the Lead. A true process death (native crash, OOM kill) leaves no marker at all with any of these hooks; that is outside this task.
- Debug console leak: `presentError` prints the unredacted exception in debug builds only (`kDebugMode`). Release builds never print it. Risk: a developer pasting debug console output into an issue on the public repo. Acceptable; suggest a note in CONTRIBUTING, not a code change.

### Round 2 probes
1. **Can the "return original if no secret decoded" switch be gamed?**
   - Secret only visible after decoding: no. The decoded and redacted text is returned for all seven forms tried (`sessionid%3D`, `%73essionid=`, `sessionid`, `&#61;`, 3x-encoded, fullwidth, zero-width).
   - Mixed plain and encoded secrets on one line: no leak, in either order, with a CDN query, and with a cookie header. Text with no secret comes back byte-identical.
   - **But the switch has a real hole, N1 (major).** If the decoded form contains any secret, the *decoded* text replaces the original, and decoding can turn `%3B`, `%2C`, `%26`, `%22`, `%20` inside a value into a value terminator. `sessionid=ZZSEC%3BTAIL` becomes `sessionid=[REDACTED];TAIL`, so TAIL leaks. Round 1 code redacted the whole `ZZSEC%3BTAIL`, so this is a **regression introduced by round 2**. Same class: `https://scontent.cdninstagram.com/a.jpg?ccb=1%20&xyz=SECRET sessionid%3D...` (the `%20` ends the URL token, so the query tail is no longer stripped). Realistic exposure is low (real `sessionid` values only contain `%3A`, which is not a terminator), but a leak that did not exist before is a fix-before-merge item. **Recommended fix:** scrub the original first, then normalise the scrubbed text and scrub again (`s1 = scrub(input); n = normalize(s1); s2 = scrub(n); return s2 != n ? s2 : s1`). Tests (skipped, fail when un-skipped): `qa_round2_test` group "N1".
2. **Over-redaction from decoding:** bounded. A harmless line that decodes into a key masks only that value token (`hello %70in%3D1234 world` becomes `hello pin=[REDACTED] world`; 50 words either side survive). Invalid escapes (`%2`, `%zz`, `\u00`, `&#99999;`, `&#x1F600;`, bare `%`) are untouched; decoding never produces control characters. Side effect (minor, info): when a secret is found, the whole line is shown decoded.
3. **4x-encoded secret (N2, minor):**
   - Key=value: 1 to 3 levels redacted, 4 levels still redacted because `%3D` is accepted as a separator, **5 and 6 levels leak**.
   - Fully encoded CDN URL: 1 to 3 levels redacted, **4 levels leak**.
   - Recommendation: acceptable in practice (nothing in the app encodes four times; input comes from our own code and Instagram responses), but cheap to harden: decode until a fixed point with a cap of 8 passes (each pass is linear; worst case still about 150 ms on 100 KB). Not a blocker.
4. **Bare-key rule, short values:** `sessionid abc`, `ds_user_id 12345`, `enc_password abc` stay unredacted (under 6 characters). Real session ids and user ids are far longer, so acceptable. Value on the next line after a bare key is not matched. The keyed form (`sessionid=a`) has no minimum. **N3 (minor):** prose after a bare key is over-redacted (`sessionid expired` becomes `sessionid [REDACTED]`); harmless noise.
5. **Line separators in the tag:** all eight (LF, CR, CRLF, VT, FF, NEL, LS, PS) are neutralised except **U+0085 (N4, minor)**: Dart's `\s` does not match it, so it is written raw. Tags are code constants or logger names, so low risk; fix by adding `\u0085` to the tag sanitiser (reuse `_lineBreak`).
6. **ReDoS re-run** (17 inputs of 100 KB, including the new decoder paths: `%41` runs, `%25` runs, `A` runs, entities, zero-width, fullwidth): worst case **157 ms** (100 KB of fullwidth characters). A 1 MB input of `%25253D sessionid ` repeated finishes under the 5 s ceiling (linear). Round 1 suite worst case was about 150 ms; no regression.
7. **Fatal-only markers still reach APP_CRASH:** yes. `PlatformDispatcher.onError`, an async zone error and a sync zone throw each produce a marker and exactly one `APP_CRASH`; `FlutterError.onError` logs but writes no marker (no APP_CRASH); five non-fatal errors followed by a fatal one still produce a marker for the fatal one; the payload has no secret even for an encoded cookie (`app/test/core/crash_hooks_qa_round2_test.dart`).
8. **Round 1 tests re-run:** all pass, GAP tests un-skipped by the developer pass. The one remaining round 1 skip (log forging) was un-skipped too.
