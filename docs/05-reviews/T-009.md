## Decision judgements

1. **ApplicationExitInfo instead of WorkInfo.stopReason: OK as an interim, conditional.** It avoids a work-runtime dependency and the data is useful for the battery diagnosis (LOW_MEMORY, USER_REQUESTED, EXCESSIVE_RESOURCE_USAGE). But it reports process deaths, not per-worker stop reasons, and starts at API 30, not 31. Condition: the Lead amends AC5 in TASKS.md and tells T-021/T-037 that per-work stop reasons must come from elsewhere if needed (for example logging `workmanager` results). The Dart doc already says `workName` is always `process`.
2. **Test deps proposed, not added: OK to defer, but AC6 stays open.** Approve the three test deps (junit 4.13.2, androidx.test ext junit 1.2.1, runner 1.6.2) and add `testInstrumentationRunner` before T-009 can be marked fully done. Without them the 99+67-line Kotlin tests are unverified code. Nothing runs them in CI.
3. **Video fallback to `Movies/Storize/<dir>/`: OK, and needed.** Android 10 MediaProvider rejects `Pictures/` for the video collection with IllegalArgumentException (caught, then retried). The returned `relativePath` reports the folder used. Condition: T-010 must store and use the returned relativePath, and the user's gallery will show videos under a Movies/Storize album, which deviates from spec §3 (document it there). Confirm in P-4.
4. **`openBatterySettings` returns a string outcome: OK.** Dart decodes it into an enum with a strict parser (unknown strings are badResponse, tested).
5. **OEM component names best-effort: OK.** Each is resolve-checked and falls back to app details. Not testable without those phones. P-4 will tell which work.
6. **API <= 28 URI is `content://` from the scan, or `file://` after 5 s: OK.** `managedUri` accepts both, and file paths are canonicalised and confined to `Pictures/Storize`. Caller must treat the URI as opaque (state this in T-010).

## Kotlin review notes

- **IS_PENDING flow:** insert(pending=1) then copy then update(pending=0). Failure paths: exception during copy, null OutputStream (explicit IOException), disk full (IOException/ENOSPC mapped to STORAGE_FULL), `update < 1`, all land in `catch (Exception)` which deletes the row and rethrows. Streams use `use {}`, no leaked cursors (`query(...)?.use`, fd `.use`). Gap: `Exception`, not `Throwable` (F6).
- **Collisions:** MediaStore silently renames to `name (1).jpg` on 29+; `FileNames.unique` does the same on the legacy path. The returned map has `uri`, `size`, `relativePath` but not the final display name (F4). `relativePath` is accurate.
- **Threading:** all media calls and lastStopReasons run on one single-thread executor. `runCatching` catches Throwable, then `mainHandler.post { deliver }` calls success/error exactly once. Rejected execution or null executor answers error once. `mainThread` calls run on the platform thread. Executor `shutdown()` in `onDetachedFromEngine`. Queued tasks still finish and post to a dead engine; harmless.
- **Thumbnails:** retriever released in `finally`, bitmaps recycled, size clamp 16..4096.

## P-4 phone checklist (for the user)

Prerequisite: Lead approves the test deps (F8) and merges. Use a debug build: `cd app && flutter run --flavor dev` (a harness or the T-010 screens must call the plugin; until then use `flutter test integration_test` or a temporary button calling `StorizePlatformAndroid`).

**Any phone (Android 10+ preferred):**
1. Insert a JPEG and a PNG with `relativeDir: "storize_test"`. Open Google Photos or Gallery: both appear in an album named `storize_test`, immediately, and the file manager shows `Pictures/Storize/storize_test/`.
2. Insert an MP4. Note which folder it lands in (`Pictures/Storize/...` or `Movies/Storize/...`) and the returned `relativePath`. It must open and play in the gallery.
3. Insert the same displayName twice. Check the file manager for `name (1).jpg`; record the returned uri and size for both.
4. Insert with a missing source path: expect `SOURCE_NOT_FOUND`. With `mime: image/gif`: `UNSUPPORTED_MIME`. With `relativeDir: "../x"`: `INVALID_ARGUMENT`.
5. Fill storage to near full (or insert a very large file) and insert: expect `STORAGE_FULL` and no ghost file in the gallery (check also with a Files app "show hidden/pending").
6. `size(uri)` equals the file size; `exists(uri)` true; `delete(uri)` returns true **with no system dialog** on Android 10+; then `exists` false, `delete` again false, and the file is gone from the gallery.
7. Try `delete` on a content URI of another app's photo (for example one taken by the camera): expect `PERMISSION_DENIED` and no dialog on Android 10+.
8. `videoThumbnail(uri: ...)` and `videoThumbnail(path: ...)`: bytes start with `RIFF....WEBP`; size at most `maxSize`.
9. `isIgnoringBatteryOptimizations()` false on a fresh install. `openBatterySettings()` shows the system "allow background" dialog; accept; call again and it should open the OEM screen (Samsung/Xiaomi/Oppo/Vivo/Huawei) or app details. Record the returned string each time and which OEM screens actually opened (Samsung: Battery; Xiaomi: Autostart).
10. `lastStopReasons()`: swipe the app away from recents, force stop it, reopen, call again; expect entries such as `USER_REQUESTED`/`USER_STOPPED` (Android 11+). On Android 10 or lower: empty list.
11. From `adb shell`: `adb shell am start -n <package>/com.amr905.storize.platform.StorizePlatformPlugin` fails (no components); `adb shell dumpsys package <package> | grep -A3 "Activity Resolver"` lists nothing from the plugin.

**Android 8-9 phone (if available):**
12. Fresh install, call `insert` before granting storage permission: expect `PERMISSION_DENIED` (F1 confirmed: nothing prompts). Grant it in app settings, retry: file appears in the gallery within 5 s, returned uri is `content://media/...` (or `file://` if slow). `delete(uri)` removes it and it disappears from the gallery.

**Emulators (AC6):** after test deps are added, from `app/android`: `./gradlew :storize_platform_android:testDebugUnitTest` and `./gradlew :storize_platform_android:connectedDebugAndroidTest` on API 28, 29 and 34+.
