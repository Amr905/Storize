## Findings
- QA-1 (Low-Med): `PageDiscovery._persist` is a non-atomic read-modify-write.
  Two isolates writing different doc_ids at once lose one (test skipped). Self-heals
  on the next page load; background rarely records.
- QA-2 (Low-Med, secrets): after logout clears the store, a stale instance (other
  isolate) that already holds tokens in memory writes them back on its next
  `record()`. Also its memory keeps serving tokens until TTL. Fix: `_persist`
  should not re-add tokens when the store entry is gone, or check session first.
- QA-3 (Low): refresher throttle is per process; a failed load repeats on each
  app start (still governed). Persist last-attempt time if desired.
- QA-4 (Low): refresher `newestAt` ignores token expiry: fresh doc_id plus tokens
  older than 12 h reports `fresh`, no refill.
- Note: verifySession bootstrap still uses REST without proof (by design, tested by
  the developer). SessionInvalid alone does not clear the discovery (only logout /
  new login does); the account status gate stops loads.

## Verdict: PASS (no blocking issue; QA-2 recommended before release).
